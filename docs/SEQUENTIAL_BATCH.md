# Поочерёдное восстановление документов с собственными образцами

## Установка на Windows / AMD

```powershell
cd C:\Projects\Improving_Docs
git pull --ff-only
.\setup_batch_windows.bat
New-Item -ItemType Directory -Force -Path input, templates | Out-Null
```

Скрипт создаёт или обновляет `.venv-ai` для Python 3.12, устанавливает базовые
зависимости, PyTorch 2.8.0 CPU, DocRes и проверенные шрифты Tinos. NVIDIA и
`nvidia-smi` не требуются. DocDiff для этого режима не скачивается.
Установщик завершает работу при ошибке, а не продолжает с неполной средой.

Плохие документы положите в `input`, читаемые образцы бланков — в `templates`.
Исходник — документ со своими реквизитами. Образец — читаемый вариант той же
формы; у него могут быть другие сведения. Оба остаются неизменными.
Не кладите образец в `input`, иначе он тоже попадёт в очередь восстановления.

## Режим с просмотром каждого документа

```powershell
.\.venv-ai\Scripts\python.exe manual_batch_review.py input
```

Этот дополнительный ручной режим запускается только командой выше.

Программа сама создаст новую папку `output/review_...` и пройдёт файлы в
алфавитном порядке. Обрабатывается один документ за раз; параллельной загрузки
моделей на несколько документов нет. Модель DocRes загружается один раз и
используется последовательно.

Для каждого документа:

1. Укажите поворот исходника: 0, 90, 180 или 270 градусов по часовой стрелке.
   Для текущего ВА-103 нужен 180, но для других документов не следует задавать
   этот поворот автоматически.
2. Выберите, будете ли предоставлять образец. Поддерживаются PDF, PNG, JPEG,
   TIFF, BMP и WebP. Если образца нет, остаётся полностраничная нейросетевая
   обработка, без переноса каркаса.
3. Укажите файл образца и его поворот. Для каждой страницы исходника выберите
   соответствующую страницу образца. Для обычной картинки номер всегда 1.
4. В редакторе слева показан исходник, справа образец. Для постоянной надписи
   выделите её полную область на обоих изображениях, впишите точный текст и
   нажмите «Добавить». `bold` — полужирный, `regular` — обычный шрифт.
   Для «(подпись)» и «(ф.и.о.)» обычно выбирается `regular`.
5. Для рамки, декоративного заголовка или знака выберите соответствующий тип:
   переносится выбранный фрагмент изображения образца. Для «Защитить область»
   выделите только исходник: эта область не должна пересекаться с каркасом.
   Защита относится к переносу шаблона; предыдущая нейросетевая стадия всё ещё
   обрабатывает исходное изображение целиком.
6. «Загрузить / проверить готовый профиль» позволяет использовать уже
   подготовленную геометрию. Для текущего ВА-103 выберите
   `profiles/va103_matched_lettering.json`. Все области отображаются поверх
   двух изображений. После проверки сохранённый профиль привязывается к новым
   точным файлам и выбранным страницам. Нельзя подтверждать профиль другого
   расположения полей без визуальной проверки.
7. Масштаб меняется кнопками «Увеличить / Уменьшить», перемещение — полосами
   прокрутки. Можно удалить неправильную область и выделить её заново.
8. Сохраните проверенный каркас. Кнопка «Эта страница без каркаса» оставляет
   для данной страницы только нейросетевую обработку. Оставшиеся страницы
   также проходят обработку; никакая страница не теряется из итогового PDF.
9. После обработки программа открывает сравнение. Затем можно перейти к
   следующему документу или закончить пакет.

В каркас включайте названия полей, постоянные должности, подписи под строками
и оформление. Не включайте фамилии, номера, даты, описание продукции, печати
и сами рукописные росчерки. Постоянная формулировка тоже может отличаться от
образца: её нужно сверять с исходником, как нижнюю строку эксперта в ВА-103.

## Что означает «нейросеть использует оригинал формы»

Текущая DocRes обрабатывает пиксели восстанавливаемого документа. Она не
обучена принимать второй сертификат как условие и автоматически извлекать
из него структуру. Подмена её входа чужим документом не реализована.

Образец используется всем конвейером: человек проверяет соответствия,
компьютерное зрение совмещает элементы, а постоянные надписи отрисовываются
чётко с размером по сохранившимся исходным буквам. Это рабочий управляемый
подход; автоматическое OCR-извлечение и классификация каркаса пока отсутствуют.
Образец не обучает модель и не добавляется в её веса.

## Результат и ошибки

В `output/review_...`:

- `index.html` — список документов, ссылки на сравнения и PDF;
- `batch_report.json` — результат каждого завершённого документа;
- `batch_config.json` — сохранённые задания для повторного запуска;
- `profiles/` — проверенные соответствия страниц;
- папка каждого документа содержит `restored_draft.pdf` со **всеми страницами**,
  PNG каждой страницы, исходный файл внутри `neural/`, отчёты и журналы.

Каждый готовый документ публикуется только после проверки всех его страниц
и совпадения PDF-растров с PNG. Ошибка документа удаляет его незавершённую
временную папку, записывается в общий отчёт и не мешает следующим документам.
Уже завершённые документы сохраняются. Исходники не перезаписываются.

Если программа прервана после нескольких документов, их результаты и
проверенные задания остаются. Полного автоматического возобновления нет:
можно повторить сохранённые задания в **новую** выходную папку или создать
конфигурацию только с оставшимися документами. Старые результаты не затираются.

## Повторить проверенный пакет без редактора

После первого интерактивного прохода:

```powershell
$review = Get-ChildItem .\output -Directory -Filter 'review_*' | Sort-Object LastWriteTime -Descending | Select-Object -First 1
$nextRun = Join-Path 'output' ('batch_' + (Get-Date -Format 'yyyyMMdd_HHmmss'))
.\.venv-ai\Scripts\python.exe restore_batch.py --config (Join-Path $review.FullName 'batch_config.json') --output $nextRun --step
Start-Process (Join-Path $nextRun 'index.html')
```

`--step` ждёт Enter перед каждым документом; без этого флага весь проверенный
список выполняется автоматически, но по-прежнему последовательно.
Пути в конфигурации считаются относительно самого JSON, а не текущей папки
терминала. Интерактивный редактор сохраняет абсолютные пути.

Формат конфигурации:

```json
{
  "schema": 1,
  "defaults": {"dpi": 200, "gain": 5, "threads": 4, "tile": 384, "overlap": 48},
  "documents": [
    {
      "input": "input/document.pdf",
      "rotate": 180,
      "reference": "templates/sample.pdf",
      "page_profiles": {
        "1": {"profile": "profiles_local/page1.json", "reference_page": 1, "reference_rotate": 0},
        "2": {"profile": "profiles_local/page2.json", "reference_page": 2, "reference_rotate": 0}
      }
    }
  ]
}
```

Для страницы можно задать собственный `reference` внутри её записи.
Если запись страницы отсутствует, в итоговый PDF включается её нейросетевая
версия и в отчёте явно стоит `neural_only`.

## Проверки

39 тестов на Linux: в том числе многостраничный TIFF, PDF-образец, шаблон
только на первой странице, отсутствие потери остальных страниц, продолжение
после повреждённого файла, одна загрузка модели на пакет, точное сохранение
пикселей вне каркаса, правильные пути конфигурации и размеры текста на слабых
исходных штрихах. Пакетные тесты используют подмену модели для детерминированной
проверки оркестрации; отдельный малый пример проверяется с настоящей DocRes.
Tkinter-модули импортированы и код GUI проверен синтаксически. Отрисовка окна
и клики на Windows пользователя пока не проверены в этой среде.
