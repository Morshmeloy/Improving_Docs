# DocDiff: первый настоящий нейросетевой режим

## После проверки пользователем: DocDiff почти не помог

На сертификате ВА-103 CPU-инференс успешно завершил 21 фрагмент по 100 шагов,
но пользователь не увидел достаточного улучшения. Устранение размытия не решило
выцветание. Кроме того, прежняя команда выбирала первый PDF вместо явно заданного,
а на сравнении область была перевёрнута. Результат не принят как финальный.

Добавлен второй нейросетевой эксперимент — DocRes `appearance`, улучшение вида
документа. Он тоже не гарантирует реконструкцию выцветшего текста. На маленьком
фрагменте заголовка из другого предоставленного сертификата изменение умеренное;
это проверка запуска, не доказательство пригодности для ВА-103.

На PDF-фрагменте ПуГВнг DocRes appearance также дал лишь слабое изменение:
средняя абсолютная разница каналов 1.73/255, заметного восстановления выцветшего
заголовка нет. Два проверенных нейросетевых режима не приняты как решение
выцветания. Не рекомендуется переходить к обработке всего пакета на их основе.
Нужен следующий эксперимент с выделением и реконструкцией чернил на исходнике.

Установка в уже существующее `.venv-ai`:

```powershell
.\setup_docres_windows.bat
```

Запуск на конкретном файле, с поворотом по часовой стрелке **до** вырезания области:

```powershell
$scan = Get-Item '.\input\Сертификат на выключатели ВА-103_ПЛОХОЙ.pdf'
$aiOut = ".\output\docres_header_$(Get-Date -Format 'yyyyMMdd_HHmmss')"
.\.venv-ai\Scripts\python.exe ai_restore.py $scan.FullName --engine docres --rotate 180 --page 1 --dpi 200 --crop 0.1 0.02 0.9 0.22 --threads 4 --output $aiOut
Start-Process "$aiOut\comparison.html"
```

Этот пример теперь проверяет верх документа после поворота, а не прежнюю нижнюю
область с подписями. Если нужен точно тот же участок, что в прежнем скриншоте,
после поворота используйте `--crop 0.1 0.78 0.9 0.98`.

Веса (~183 МБ) скачиваются из демонстрации, указанной авторами DocRes в README:
https://huggingface.co/spaces/qubvel-hf/documents-restoration
Закреплены revision и SHA-256 в `docres_manifest.json`. Архитектура скачивается
из официального GitHub. Загрузка `weights_only=True`, CPU float32, строгая проверка
архитектуры и весов. Данные документа остаются локально.

Адаптация: глобальный appearance prompt вычисляется по выбранному фрагменту в BGR,
после чего выполняется нейросетевой инференс на перекрывающихся фрагментах без
уменьшения исходных пикселей. Авторский код на больших страницах уменьшает вход
до 1600x1600; здесь используется нарезка, поэтому это не буквальное воспроизведение
цельностраничного режима и результаты могут отличаться. Веса и архитектура неизменны.
В HTML теперь указан выбранный файл, страница, поворот и величина изменения пикселей;
эти значения не являются оценкой восстановления букв.

Локальные проверки: 18 тестов проекта, реальный DocRes-инференс фрагмента заголовка
с двумя перекрывающимися тайлами и PDF-фрагмента. Windows-установка DocDiff
подтверждена логом пользователя; DocRes на его Windows пока не проверен.

---

Этот режим использует официальные обученные веса **устранения размытия** DocDiff.
Исходный проект: https://github.com/Royalvice/DocDiff
Статья: https://arxiv.org/abs/2305.03892
Код и веса закреплены на commit `f422a3af10657eeabeca90f2e862d88c72725845`.
MIT-лицензия скачивается вместе с моделью. Данные документов никуда не отправляются.
При установке скачиваются только код и веса, суммарно около 33 МБ; PyTorch отдельно.

## Windows, AMD RX 6650 XT: CPU

В PowerShell из корня проекта:

```powershell
.\setup_ai_windows.bat
.\.venv-ai\Scripts\python.exe -c "import torch; print(torch.__version__); print('CPU threads:', torch.get_num_threads())"
```

Установка использует отдельное `.venv-ai`. Активация PowerShell не нужна.
CUDA не устанавливается. Видеокарта AMD в этом режиме не используется.
FP32 выбран для совместимости CPU. Качество на документе требует сравнения.

Для первого опыта поместите исходный скан в `input\certificate.pdf`:

```powershell
.\.venv-ai\Scripts\python.exe ai_restore.py .\input\certificate.pdf --output .\output\ai_header_001 --page 1 --dpi 200 --crop 0.1 0.02 0.9 0.22 --threads 4
Start-Process .\output\ai_header_001\comparison.html
```

`--crop`: X0 Y0 X1 Y1 — доли ширины и высоты исходной страницы. В примере
обрабатывается верхняя полоса; при другом расположении заголовка координаты нужно изменить.
Сначала сравните `original.png` и `docdiff.png` при увеличении: конкретные буквы,
цифры, тонкие линии. Затем попробуйте подпись с подходящими координатами.
Без `--crop` обрабатывается вся выбранная страница; это может быть долго на CPU:

```powershell
.\.venv-ai\Scripts\python.exe ai_restore.py .\input\certificate.pdf --output .\output\ai_page1_001 --page 1 --dpi 200 --threads 4
```

Страница 2 запускается отдельно с `--page 2` и новой папкой вывода.
Режим сохраняет PNG и HTML-сравнение, **пока не формирует итоговый PDF и не делает пакет файлов**.
Существующая папка вывода не перезаписывается: для повтора меняйте `001` на `002`.

## Что делает модель

1. Coarse Predictor (U-Net) получает RGB 0..1 и предсказывает основную структуру.
2. Второй U-Net уточняет высокочастотный остаток за 100 обратных шагов диффузии.
3. Остаток складывается с основным предсказанием.
4. Фрагменты идут без уменьшения масштаба, с перекрытием 64 пикселя и плавным
   смешиванием. Отдельные фрагменты могут дать отличия от цельностраничного инференса.

Используется авторская линейная beta-схема и предсказание x0. Seed фиксирован.
У адаптации убран CUDA-тензор из значения аргумента по умолчанию в авторском коде;
модель всегда получает явный timestep. Веса загружаются с `weights_only=True`, строго
проверяются размеры, Git blob SHA-1 и соответствие архитектуре. Установка не скачивает
веса `seal_*` для удаления печатей. Это не гарантирует сохранение печати: проверяется визуально.

Модель обучена устранять размытие; исчезнувшие от выцветания чернила — другое
искажение. Результат эксперимента может оказаться слабым или изменить символы.
Текущий режим не распознаёт буквы и не перепечатывает текст, не реконструирует
рамку по геометрии и не применяет ручные защищённые области старого режима.
До переноса в итоговый PDF нужны проверки заголовка, мелкого текста, подписи и печати.
