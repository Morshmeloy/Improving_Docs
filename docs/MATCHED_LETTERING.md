# Чёткий восстановленный текст с размером и стилем ближе к оригиналу

Пользователю понравилась читаемость варианта `va103_fields_final_v2`, но не
подходили шрифт и размер. Возврат к зернистым исходным буквам не решал задачу.
Текущий режим `metric_matched_text` сохраняет чёткие восстановленные надписи
и исправляет их типографику. Основой результата служит именно понравившаяся
читаемая версия, а не бледный исходник.

## Что исправлено

- Вместо DejaVu Serif используется Tinos Bold; для номера, серии и маленьких
  служебных подписей — Tinos Regular. Форма букв визуально ближе к исходной.
  Точное название исторического шрифта по скану не установлено.
- Размер вычисляется по видимому прямоугольнику исходных букв. Большой
  прямоугольник очистки больше не определяет высоту шрифта.
- Надпись остаётся чёрной и цельной, без возвращения зернистости исходника.
- Верхняя плашка, рамка, знак EAC, индивидуальные сведения, номера, печати и
  росчерки сохраняются из понравившейся версии.
- Нижняя служебная строка эксперта уточнена по видимому оригиналу:
  `(эксперты (эксперты-аудиторы))`. В исходнике она длиннее строки образца;
  это различие нельзя игнорировать при выборе формулировки и размеров.

`matched_lettering.py` набирает только проверенные постоянные формулировки
при большом внутреннем размере, затем OpenCV укладывает растр в измеренные
границы исходных букв. Горизонтальный и вертикальный масштабы могут немного
различаться, чтобы совпали ширина и высота. Это приближение к исходной
типографике, не доказательство точного совпадения шрифта или кернинга.
Положение отдельных букв автоматически по исходнику пока не восстанавливается.

Все 21 текстовый элемент получил размер по исходнику. Знак EAC остаётся
чистым изображением из прежнего профиля, без набора новым шрифтом.
Пиксели за пределами выбранных областей и внутри защищённых областей
точно совпадают с читаемой основой. Растр PDF проверен против сохранённого PNG;
PDF отрендерен и просмотрен. 36 тестов прошли на Linux.

## Одинаковый шрифт на Windows и Linux

`setup_fonts.py` скачивает Tinos из официального репозитория
[Google Fonts](https://github.com/google/fonts/tree/ba95515f1333efe9342c2ad988b9c2f6bef6dbad/ofl/tinos)
по фиксированной ревизии `ba95515f1333efe9342c2ad988b9c2f6bef6dbad`, проверяет
размер и Git blob SHA-1 каждого файла и сохраняет в `models/fonts`.
Используется выпуск Tinos 1.340, обозначенный upstream как OFL release.
Автоматической подмены отсутствующего шрифта системным нет: программа просит
выполнить установку. Загруженные шрифты не коммитятся в пользовательский репозиторий.

## PowerShell

Укажите реальные пути своего исходника, образца и **читаемой версии с крупным
шрифтом**. Последняя будет основой: содержимое не нужно обрабатывать заново.

```powershell
cd C:\Projects\Improving_Docs
git pull --ff-only
.\.venv-ai\Scripts\python.exe setup_fonts.py
.\.venv-ai\Scripts\python.exe template_restore.py --source "input\Сертификат на выключатели ВА-103_ПЛОХОЙ.pdf" --base "output\va103_fields_001\reconstructed.png" --reference "input\template.png" --profile "profiles\va103_matched_lettering.json" --output "output\va103_matched_001" --dpi 200 --rotate 180
Start-Process "output\va103_matched_001\comparison.html"
```

Если основы ещё нет, можно сначала получить читаемую версию по предыдущей
инструкции `STATIC_FORM_ATLAS.md`, затем применить этот профиль к её PNG.
Папка результата должна быть новой. Профиль привязан SHA-256 к конкретному
исходнику и образцу и не является универсальным для других сертификатов.
Режим обрабатывает одну выбранную страницу. На Windows команда пока не
выполнялась на ПК пользователя; Linux-версия с реальными шрифтами проверена.

## Ограничения

Размеры оцениваются по сохранившимся пикселям исходника: шум или отсутствующий
хвост буквы могут повлиять на измерение. Чёрный восстановленный текст визуально
плотнее бледного скана. Это желаемая читаемость, но не точная копия старой печати.
Индивидуальное содержимое остаётся прежней обработанной картинкой; эта стадия
не переписывает имена, даты, реквизиты или рукописные подписи.
