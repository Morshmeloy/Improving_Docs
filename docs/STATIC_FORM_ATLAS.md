# Образец как словарь и карта структуры документа

Наборный шрифт оказался неподходящим. Для сохранения оригинального
начертания при сохранении чёткой реконструкции используйте
[актуальный режим](MATCHED_LETTERING.md). Ниже — описание
предыдущего эксперимента с повторной отрисовкой.

Первая версия переноса шаблона использовала только рамку и два заголовка.
Это было слишком узкое определение каркаса. Новая версия использует ещё
названия разделов, должности, обозначения полей и служебные подписи под строками.

## Что извлекается из образца

У каждого элемента есть три независимые части:

1. **Смысл:** точная постоянная формулировка, проверенная человеком по образцу.
2. **Роль:** название поля, служебная подпись, постоянный знак или орнамент.
3. **Геометрия:** отдельные координаты на образце и на восстанавливаемой странице.

Образец задаёт состав формы, а не реквизиты конкретного сертификата.
Строки данных расположены по-разному, поэтому переносить блоки страницы целиком
или совмещать все слова одной общей матрицей нельзя.

`profiles/va103_template_fields.json` содержит 22 дополнительных элемента:

| Группа | Проверенные элементы |
|---|---|
| Разделы | ОРГАН ПО СЕРТИФИКАЦИИ; ЗАЯВИТЕЛЬ; ИЗГОТОВИТЕЛЬ; ПРОДУКЦИЯ |
| Требования и основания | КОД ТН ВЭД ЕАЭС; СООТВЕТСТВУЕТ ТРЕБОВАНИЯМ; СЕРТИФИКАТ СООТВЕТСТВИЯ ВЫДАН НА ОСНОВАНИИ; ДОПОЛНИТЕЛЬНАЯ ИНФОРМАЦИЯ |
| Срок действия | СРОК ДЕЙСТВИЯ С; ПО; ВКЛЮЧИТЕЛЬНО |
| Должности, по две строки | Руководитель (уполномоченное лицо) органа по сертификации; Эксперт (эксперт-аудитор), (эксперты-аудиторы) |
| Служебные подписи | Два обозначения (подпись) и два обозначения (ф.и.о.) |
| Постоянные обозначения | № ЕАЭС; Серия; знак EAC |

Слово «подпись» в скобках является каркасом. Сам росчерк — индивидуальное
содержимое. Аналогично «(ф.и.о.)» — постоянная надпись, а фамилия рядом с ней
не должна поступать из образца. `RU` остаётся из исходной нейросетевой основы.

## Как применяется информация

`template_restore.py` поддерживает два новых способа:

- `verified_label_text`: повторная отрисовка проверенного постоянного текста
  с помощью Pillow, затем совмещение растра в заданной области через OpenCV.
  Это управляемая реконструкция типографики, не OCR и не генерация реквизитов.
  Шрифт Times New Roman Bold на Windows или DejaVu Serif Bold на Linux;
  точное совпадение исторического шрифта не гарантируется.
- `ink_label`: OpenCV выделяет чёрные малонасыщенные чернила образца,
  удаляет компоненты меньше двух пикселей и совмещает маску букв/знака.
  Цветные росчерки и печати отбрасываются по цветовой эвристике.
  Эта эвристика не распознаёт смысл и не гарантирует разделение перекрытых
  чёрных подписей и букв. В испытанном профиле так перенесён только знак EAC.

В испытанном примере служебный текст отрисован заново: фрагменты мелкого
шрифта образца сами повреждены, а часть должности пересечена синей подписью.
Перед этим формулировки вручную сверены с образцом и исходником. Это не
нейросетевое распознавание; нейросеть DocRes продолжает применяться для основы
с индивидуальным содержимым. Новые режимы требуют `reviewed: true` и
`verified_text`. Простого предположения по образцу недостаточно.

Перенос разрешён только в конкретных областях каркаса. Для индивидуальных
данных есть дополнительные защищённые прямоугольники; пересечение вызывает
ошибку. Все пиксели вне маски разрешённых изменений проверяются на точное
совпадение с основой. Около подписей области особенно узкие, чтобы сохранить
росчерки, линии и печати. Фон внутри разрешённой надписи заменяется светлым.

## Запуск для текущего примера

Используйте собственные фактические пути исходника, основы и образца:

```powershell
cd C:\Projects\Improving_Docs
git pull --ff-only
.\.venv-ai\Scripts\python.exe template_restore.py --source "input\Сертификат на выключатели ВА-103_ПЛОХОЙ.pdf" --base "output\va103_whole\page_0001_reconstructed.png" --reference "input\template.png" --profile "profiles\va103_template_fields.json" --output "output\va103_fields_001" --dpi 200 --rotate 180
Start-Process "output\va103_fields_001\comparison.html"
```

Основа — результат прежнего `ink_reconstruct.py --whole-document`.
Необходимо установить базовые зависимости; новые нейросетевые веса не нужны.
Профиль привязан SHA-256 к конкретному исходнику и образцу. Изменённый или
пересохранённый образец требует нового проверенного профиля. Это профиль одной
страницы, не универсальное решение для всех сертификатов.

## Что ещё образец даёт для развития

Словарь статических полей позволяет строить отдельные области данных между
проверенными заголовками и задавать для них обработку исходных пикселей:
мелкий печатный текст, большие буквы, числовые реквизиты, печати и росчерки
требуют разных параметров. Однако автоматическая сегментация этих областей,
OCR-сопоставление шаблонов и автоматический подбор силы DocRes пока не
реализованы. В этой версии положения элементов проверены вручную.

Не переносим повторяющиеся слова вроде «Место нахождения» вслепую: в исходнике
они могут входить в сплошной абзац, а в образце стоять отдельной строкой.
Не добавляем поля, которых нет на исходном бланке, и не заменяем фамилии,
даты, сертификатные номера, нормативные ссылки и текст продукции по образцу.

## Проверки и ограничения

30 тестов прошли на Linux. Проверяются сохранение переменных данных вне
каркаса, отбрасывание цветного росчерка в режиме выделения чернил, отказ
отрисовывать непроверенную формулировку, запрет пересечения с защищёнными
областями и совпадение растра PDF с PNG. Реальный PDF отрендерен и просмотрен.
Windows-шрифт и запуск на ПК пользователя ещё требуют проверки; шрифты
Windows и Linux дадут разные формы букв.

Это черновая реконструкция каркаса. Точность содержимого исходной
нейросетевой основы не подтверждается тем, что каркас стал читабельным.
